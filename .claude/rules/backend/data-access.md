# 外部の保存先からの読み取り（Neon・R2・Clerk などの外部 API）

Neon（PostgreSQL）・R2・Clerk などの外部 API は、1 回の呼び出しごとに往復の待ち時間がかかり、従量課金のものは料金もかかる。読み取りの回数は「件数に比例して増えるか」で見る。テストは件数の少ないデータで回るので、件数に比例する読み取りは緑のまま本番で遅くなる。

## 1 件ずつ取りに行かない（N+1）

- **一覧を取ってから 1 件ずつ中身を取りに行く形にしない。** 必要な中身を一覧と一緒に返す読み方を選ぶ。どうしても後から取るなら、まとめて取る形にする
  - Neon（Drizzle）: 一覧の各行に紐づく行（いいね数・投稿者など）は、join か `inArray` で 1 回にまとめて引く。行ごとに `select` を投げない
  - Clerk: ユーザー情報を一覧の件数ぶん `getUser` しない。まとめて取る API（`getUserList` の `userId` 指定など）を使う
  - R2: 同じオブジェクトの存在確認（`head`）と取得（`get`）を続けて呼ばない。取得の応答で大きさも分かる。ただし、本体を読む前に大きさで弾くための確認は残す
- **ループの中で同じ一覧を読み直さない。** ループの前に 1 回読み、手元で絞る
- **1 回の処理（1 リクエスト）の中で、同じ id を 2 回読まない。** 読んだものを手元に残し、後の段に渡す。残すのはその処理の中だけにし、リクエストをまたいでモジュールに置かない（ユーザー・権限の境界を越えて残るため）。ただし、最新の状態で判断・書き込みする必要があるとき（条件付きの書き込みの直前・状態の遷移の判定）は読み直す。手元に残した古い値で判断すると、その間のほかの人の更新を上書きする

## 待ち方

- **互いに依存しない読み取りは並列にする。** `Effect.all` / `Effect.forEach` は、`concurrency` を書かないと 1 本ずつ順番に動く
- **並列にしたら、どの失敗を先に返すかを決める。** 前提の確認（対象が存在するか・権限があるか）と本体の読み取りを並列にすると、先に終わった方の失敗が返る。前提の失敗を優先して返す。そうしないと、404 になるべきものが 500 になる

## 絞り込みは読む側（SQL）でやる

- **条件で絞る一覧は、`WHERE` で絞ってから `LIMIT` する。** 多めに読んでから手元で絞ると、1 ページに満たない結果に「次のページ」のカーソルが付いて返る
